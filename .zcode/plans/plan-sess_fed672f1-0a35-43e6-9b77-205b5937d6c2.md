### Z-Library eAPI flow

1. **Login**: `POST {base}/eapi/user/login` with `email` + `password` form fields → extracts session cookie (`remixsid` or similar)
2. **Search**: `GET {base}/s/{query}` with session cookie → JSON with books array (id, title, authors, extension, hash, cover, description, year, filesize)
3. **Download**: `GET {base}/dl/{hash}` with session cookie → streams EPUB

Session stored in-memory, invalidated on credential or mirror change. 401/403 triggers re-login. Download manager has 2-attempt retry which handles transient session expiry.

### Settings fields (Z-Library credential form)
- Email (text input)
- Password (password input)  
- Base URL (text input, placeholder: "https://singlelogin.re" or current mirror)
- Save button

### Key design decisions
- **User-provided mirror URL** (not fleet-managed) — Z-Library mirrors rotate frequently; user knows their working URL
- **Email+password auth** — most common access pattern; sessions survive across mirror changes (SSO)
- **In-memory session only** — no disk persistence; credentials are stored, re-login happens automatically
- **Adapter stays in `internal/sources/`** (not `sources_optin/`) for v1 — easier to iterate; extract later under pressure per spec
- **`NeedsAuth()` returns true until both email AND password are provided** — prevents search from firing without credentials
